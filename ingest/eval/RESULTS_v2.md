## 邊樣改動出到力

**1. 多重 query fallback（最大功臣，JP +12%）**

剝走地區／品類前綴之後先再搵一次：

| 原本搵唔到 | 剝完之後 |
|---|---|
| `亀十` | `御菓子司 亀十` ✅ |
| `浅草九重` → `九重` | ✅ |
| `和菓子 楓` → `楓` | ✅ |
| `かりんとう小桜` → `小桜` | ✅ |
| `中華 幸軒` → `幸軒` → `Saiwaiken` | ✅ |
| `菊水堂`、`木村屋本店`、`BURDIGALA` | ✅ |

**2. `name:ja` / `name:en` / `alt_name` 全部比一次**

`丸豊` 對 `Marutoyo` 嘅字元相似度係 **0**。單靠 display name 一定死。
要攞 OSM 嘅 `namedetails` 同所有別名比，取最高分。日本配對嘅關鍵。

**3. 類別過濾（擋走 5 個錯配）**

| 抽到 | 曾經配到 | OSM 類別 |
|---|---|---|
| 夜嗜野 | 基督教香港信義會尊聖堂 | `amenity/place_of_worship` |
| 寶樹堂 | 保良局唐乃勤初中書院 | `amenity/school` |
| and TOKYO | 東京都 | `boundary/administrative` |
| 浅草製作所 | 犬印鞄製作所（賣袋） | `shop/bag` |
| and TOKYO | and ST（賣衫） | `shop/clothes` |

最後兩個唔可以一刀切否決 `shop/*` —— `曲奇四重奏` 喺 OSM 標咗
`shop/gift`，佢真係間餅店。改成**重罰**（類別分 0.15），
名完全一樣嘅照樣過（0.86），名唔似嘅就跌出局。

## 三個開發途中捉到嘅自己友 bug

呢啲全部係「數字睇落合理但係錯」嗰種：

1. **Substring 加分太鬆** —— 我原本寫「短嗰個係長嗰個嘅子字串就畀 0.92 分」。
   結果 `and` 喺 `and TOKYO` 入面攞到 0.95，`place` 對 `231 PLACE` 攞到 0.96。
   改成要夠覆蓋率先算數。

2. **修完之後過度收緊** —— `亀十` 對 `御菓子司 亀十` 跌到 0.50。
   真正嘅分別唔喺長度，喺**辨識度**：CJK 兩個字已經好獨特，
   英文三個字母乜都唔代表。要分開兩套門檻（CJK 覆蓋率 0.30／拉丁 0.55）。

3. **拉丁品牌名共用尾巴** —— `BAKE CHEESE TART` 對 `Pablo cheese tart`
   difflib 畀 0.76，但佢哋係競爭對手。加咗頭一個字嘅檢查。
